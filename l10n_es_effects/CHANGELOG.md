# Changelog

## 18.0.4.3.3 — 2026-11-05

- Pending grouping/remittance projections synchronize bank and beneficiary bank selections with their source records.
- Remittances created from selected effects or from a grouping generate the initial transfer entry automatically; draft changes rebuild the same move.
- Partial grouping payments retain paid tranches as active portfolio records and resize/archive only the pending continuation.
- Paid tranches expose their own annulment and return actions; only the latest tranche can annul a shared operation.
- Native Odoo payments receive an explicit `cartera_settled` marker so posted cartera settlements display as Paid instead of In Process when a transit account is involved.
- The payment register preselects the container/effect bank journal or an available liquidity journal.
- Payment memo/reference identifies the effect, grouping or remittance with its corresponding number.
- Settlement returns to the current cartera form instead of opening the native payment/accounting entry.
- Removing effects from an unpaid draft remittance refreshes its original opening entry; an emptied draft remittance cancels that entry and reuses the same move if effects are added again.
- A remittance created from a grouping preserves the default bank journal; direct creation of a group/remittance also preserves model defaults when no bank is explicitly selected.
- Removed the manual grouping-confirmation button; the opening grouping entry is generated by the save/add-effects flow.
- Static validation passed (Python compile, XML parse, manifest file references and access CSV); no live Odoo 18 runtime tests were available.

## 18.0.4.3.2 — 2026-11-05

- Residual effects copy the circular/concept reference from the source effect or grouping.
- Fixed unsupported `fields.Date.min/max` references.
- Improved remittance payment reversals and bank journal defaults.
- Added direct settlement for manually-created effects without invoices.

## 18.0.4.3.1 — 2026-11-05

- Automatic grouping entry and remittance partial-selection improvements.
- Return availability now follows paid allocations, including grouped effects.
- Consolidated payments are visible in native customer/vendor payment lists.

## 18.0.4.3.0 — 2026-11-04

- Initial grouping reclassification entry and single-entry group/remittance settlements.
- Partial group settlement allocations and whole-effect partial remittance selection.
- Multi-customer settlements represented by one accounting entry and per-partner native payment records.
